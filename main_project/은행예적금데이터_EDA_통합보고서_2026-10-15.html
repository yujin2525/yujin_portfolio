01은행 예적금 데이터 구성과 분포

팀 공유용 데이터 설명서

작성일 2026년 10월 15일 | 분석 대상 personal_ai.sqlite

이 문서는 은행 예적금 데이터의 테이블 구성, 컬럼 의미, 관측값 분포와 분석 기준을 설명한다. 팀원이 데이터 조회와 후속 분석을 시작할 때 무엇을 집계할 수 있고 어떤 식별·품질 제약을 고려해야 하는지 이해하는 것이 목적이다.

핵심은 1,173명의 고객에 연결된 기본정보 12,986행, 상세정보 17,324행, 거래내역 848,187행으로 구성된다는 점이다. 입출금성 상품도 포함되며, 계좌번호와 거래번호가 각각 하나의 값으로 익명화되어 실제 계좌 수와 고유 거래 수는 확정할 수 없다.

문서 읽는 순서

목차에서 데이터 구조·분포·품질, 전체 컬럼 사전, 거래 메모 및 리워드 분석으로 이동할 수 있다. 컬럼 사전의 의미 설명은 이름과 기존 EDA에 근거한 해석이며 코드의 공식 정의와 구분한다.

본 문서의 통계는 현재 DB의 규모·식별자·주요 분포를 다시 확인하고 기존 EDA 결과와 대조했다. 개인별 실명·연락처·거래 적요 원문은 수록하지 않는다.

행 수와 고객 수를 구분하는 이유

고객 한 명이 여러 상품·통화와 여러 거래를 가질 수 있고 동일 업무값의 반복 행도 있다. 따라서 행 수, 고유 고객 수, 상품명 수, 임시 관측그룹 수는 서로 다르다. 고객 수는 기관·상품 분류 사이에 중복되므로 분류별 고객 수를 합산해 전체 고객 수로 사용하지 않는다.

03연결 관계와 값 해석 기준

검증된 고객 단위 연결

은행 세 테이블의 id는 모두 UserInfo의 id에 연결된다. UserInfo의 id는 1,173개로 중복이 없어 은행 관측 N행 → 고객 1행의 연결이 가능하다. 고객 속성을 붙일 때는 many-to-one 검증을 적용한다.

계좌 단위 연결은 임시 관측그룹으로만 사용

기존 EDA는 id + companyName + accountName + accountType + 통화 조합을 임시 관측그룹으로 사용했다. 기본정보와 상세정보는 각각 9,023그룹이지만 서로 91그룹씩 일치하지 않는다. 거래는 9,063그룹이며 기본정보에 없는 그룹이 210개다. 이 조합도 검증된 계좌키가 아니다.

같은 고객이 같은 상품의 계좌를 여러 개 보유하면 하나로 합쳐질 수 있고, 상품명이나 유형 표현이 다르면 같은 계좌가 여러 그룹으로 나뉠 수 있다. 최신행을 선택해도 실제 계좌의 최신 상태가 보장되지 않는다.

금융 테이블끼리 id만으로 직접 조인하지 않는다

고객별 기본정보 M행과 거래 N행을 id만으로 연결하면 최대 M×N행으로 늘어날 수 있다. 고객별 또는 고객·통화별로 먼저 집계한 뒤 연결하고, 조인 전후 행 수와 금액 합계를 확인한다. 계좌별 거래 연결은 계좌 식별자가 복원되기 전까지 확정할 수 없다.

저장형과 의미형을 분리한다

메타데이터 3개는 INTEGER, 나머지는 TEXT로 선언되어 있다. 다수 업무값은 JSON 표현 문자열이므로 먼저 json.loads 방식으로 해석한다. 예를 들어 저장값의 따옴표를 해제한 뒤 금액은 숫자로, 시각은 날짜로 변환한다. true·false도 문자열로 남을 수 있어 명시적으로 매핑한다.

SQL NULL, JSON null, 문자열 null, 빈 문자열, 마스킹 문자열은 서로 구분한다. 값이 존재한다는 사실만으로 분석에 유효하다고 판단하지 않는다. person_key는 추정 연결키로, 다른 도메인의 동일인 연결을 보장하지 않는다.

정기예금 후보의 잔액 중앙값은 1,200만 원, 청약은 400만 원, 적금·적립형은 90만 원이다. 입출금성 후보와 파킹·분리보관 후보의 중앙값은 각각 1,229.5원과 9,142원이다. 저축 방식과 상품 목적이 다르므로 이 차이를 저축 성과의 우열로 해석하지 않는다.

금리 중앙값은 청약 3.1, 적금·적립형 3.0, 정기예금 2.6, 파킹·분리보관 후보 1.6, 입출금성 후보 0.1이다. 한도·우대조건·기간이 반영되지 않아 상품 추천 순위로 사용하기 어렵다.

분류에서 남는 불확실성

확인 필요가 1,324행으로 전체 비교 표본의 13.40%다. 이 범주를 숨기거나 제외하면 특정 상품군의 비중이 과대평가될 수 있다. 파킹·분리보관 후보에는 저금통처럼 성격이 다른 상품이 포함되므로 개별 상품 검증이 필요하다.

업무값 완전동일 추가 행 제외의 의미

메타데이터와 person_key를 제외한 모든 원본 업무값이 동일한 추가 행만 제외했다. 동일한 값을 가진 서로 다른 계좌까지 합쳐질 수 있으므로 확정된 중복 제거가 아니다. 보고서에서 비교용 표본이라고 부르는 이유다.

원천은 프로젝트 루트의 personal_ai.sqlite 내 raw_bank_part1_ 테이블 4개다. 이 문서 작성 시 읽기 전용으로 조회했다. DB의 행·열 수, 고객 연결, 번호 고유값, 업무값 완전동일 추가 행, 원화 표본 크기, 월별 거래 행 수를 재확인했다.

은행별 관측 규모와 잔액·금리 전체 분위수 및 컬럼 프로파일은 현재 DB에서 다시 계산했다. 기존 EDA의 임시 그룹 최신행 통계를 원화 9,882행 비교 통계와 혼합하지 않았다.
